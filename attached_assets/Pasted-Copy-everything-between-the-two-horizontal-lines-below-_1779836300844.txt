Clustering logic (this is the load-bearing part — please read carefully):

Trigger: clustering runs once, the first time the user reaches Step 4. After that, state.mirror4.clusters is the source of truth and never re-runs automatically.
Implementation: single client-side fetch to the Anthropic API, reusing the existing pattern from M1's peel summary and M3's behavior bullets. Locate the existing fetch code (likely around App.tsx lines 41517, 41522, 42063 — the ones used for userId || "The user" summary prompts). Do not add a new server endpoint, do not call from the backend, do not add new auth/credential wiring. Use the same fetch shape that's already working in M1/M3.
Prompt: send the full state.mirror4.portrait (all behaviors with their tier tags) and ask for 2–4 thematic clusters returned as JSON:

json  {
    "narrative": "string — Katherine's one-paragraph intro for the Step 4 cyan card",
    "clusters": [
      {
        "proposal": "string — short phrase like 'accountability — owning your impact'",
        "proposedNames": ["string", "string", "string"],
        "behaviorIds": ["ad-1", "ir-3", "ad-4"]
      }
    ]
  }

On success: write to state.mirror4.clusters[] with stable IDs (cl-1, cl-2, …) and assign color by creation order — first cluster = c1, second = c2, third = c3. Fourth and fifth (which only arise via add-another in Step 8) cycle back to c1, c2. Color is locked at creation; rank order changes do NOT change color.
On fetch failure or malformed JSON: fall back to a rule-based cluster. Group all lights + warms portrait behaviors into one cluster (cl-1) with proposal: "From what lights you up" and proposedNames: ["Integrity", "Honor", "Self-Trust"]. Group all bothers + turns behaviors into a second cluster (cl-2) with proposal: "What you refuse to tolerate" and proposedNames: ["Respect", "Honesty", "Standards"]. Set narrative: "Here's how I'd group your portrait — work each one and see what value lives underneath.". Log a console warning so we can spot it during dev walks.
2-cluster soft prompt: if the Anthropic call returns only 2 clusters, prepend to the narrative: "I see two — values usually run deeper than that. After we work these, look at what's left in your portrait." This is a soft hint for the user to use add-another in Step 8.
Dev-only re-cluster link: add a small underlined gold text link in the Step 4 footer reading "Re-cluster from portrait" (faint, easy to miss). Click → wipes state.mirror4.clusters, re-runs the Anthropic call. Useful during dev walks. Wrap in a DEV_MODE check if one exists, or just leave it discreet — Katherine can ignore it.
