Bug 4 — Overlay first-paint bleed-through is STILL HAPPENING. When the Superpowers overlay opens from the hub, hub content (breadcrumb "Identity · Your Gifts & Shadows", cluster cards Your Gifts / Superpowers / Under Pressure / Own It) bleeds through the new overlay heavily on first open. Cleans up after the user scrolls — but the first-paint experience is messy. Your last commit said this was fixed, but visual evidence shows the hub is still showing through on first paint.
Diagnosis steps to find the actual cause:

Inspect the overlay container's computed background in DevTools after it opens. If it's rgba(...) with any alpha < 1, OR transparent, OR no background-color set, that's the bug.
Check for a fade-in transition or opacity animation on the overlay container. If the overlay animates from opacity: 0 to opacity: 1 over 200ms+, the hub is visible during that fade. Either remove the fade or ensure the overlay paints fully opaque from frame 1.
Check the hub container z-index vs overlay z-index. If they're close (e.g. hub at z-index 10 and overlay at z-index 11), some stacking-context shenanigans could let hub show through. Overlay should be z-index 50+ above hub, or hub should get visibility: hidden the moment the overlay opens.
Check for paint timing race. If the overlay's children render before the overlay's own background paints, you'll see hub through transparent gaps. Solid background-color on the overlay container (same --bg-card navy as the rest of the card) usually fixes this.

The fix is one CSS block — either backdrop opacity, paint timing, z-index, or visibility toggle on the hub. Don't ship a guess; inspect the live DOM first to confirm which.
