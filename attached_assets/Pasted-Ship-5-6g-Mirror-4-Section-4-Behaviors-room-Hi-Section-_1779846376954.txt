Keystone prompt (gold-warm card at bottom of screen)
Below the behavior cards, before the footer:

★ icon centered
Title: Mark the keystone
Body: The one behavior you'd defend first — the one that proves the value is real. Tap the star on whichever behavior carries it.
Skip — they're all equal to me link (underlined gold, small)

Behavior:

Initial state: no keystone marked, prompt visible with full body text
User clicks a star on any behavior card → that behavior becomes the keystone (state: state.mirror4.operationalize[clusterId].keystoneId)
Only one keystone per value (clicking another star moves it)
Once keystone is marked: prompt collapses to a quiet line: Keystone set: "[behavior name]". The skip link disappears (already chose).
Skip link sets keystoneId = null and dismisses the prompt


Behavior pre-fill from Discover
For each value (cluster) on first entry to Behaviors:

Look at cluster.behaviorIds (the portrait behaviors that landed in this cluster)
Look at cluster.flips where accepted === true (the accepted flip commitments)
Build initial state.mirror4.operationalize[clusterId].behaviors:

For each behaviorId in cluster.behaviorIds: create a behavior with name = admire[id].text || irks[id].text, source = tier of that behavior (lights/warms/bothers/turns), practice = []
For each accepted flip: create a behavior with name = flip.to, source = "flipped", practice = []
For each "new" typed behavior added on the per-value screen (source NEW in 3a): create a behavior with name = text, source = "new", practice = []


Order: Lights → Warms → Flipped → New (group by source)
Cap initial pre-fill at 5; if there are more, drop the lowest-intensity ones (warms before lights, etc) and add a small note: Trimmed to 5 — your strongest behaviors made the cut.

This pre-fill only runs once per value — first time the user opens Behaviors with that value active. After that, state.mirror4.operationalize[clusterId] is the source of truth and user edits persist.

State schema additions
state.mirror4.operationalize is keyed by cluster ID. The schema from Section 1 already supports it:
typescriptoperationalize: Record<string, {
  behaviors: Array<{
    id: string;
    name: string;
    practice: string[];
    source: "lights" | "warms" | "flipped" | "new";
    sourceBehaviorId: string | null;
  }>;
  keystoneId: string | null;
}>;
Use this verbatim. ID prefix for behaviors: b- (e.g. b-1, b-2, ...). All writes through saveMirror4State(). State resume from 5.6c routing — refresh inside Behaviors with a value selected should return user to Behaviors with the same value active.
Active value: store as state.mirror4.behaviorsActiveClusterId so refresh returns the user to the same value they were editing. (Or use the per-room state pattern Agent prefers — small detail.)
