**Pair generation rules**

For N named values:
- Generate all `N×(N-1)/2` pairs **in rank order, adjacent-first** (e.g. for 4 values ranked [Honesty, Loyalty, Courage, Discipline], pairs are: Honesty-Loyalty, Loyalty-Courage, Courage-Discipline, Honesty-Courage, Loyalty-Discipline, Honesty-Discipline — adjacent first, then jumping)
- **Cap at 10 pairs.** If `N >= 5` (which gives 10+ pairs), cap by:
  - Take all adjacent pairs first (`N-1` pairs)
  - Then fill remaining slots up to 10 with random non-adjacent pairs (use a deterministic seed based on rank order so the selection is stable across re-renders)
- **Re-roll trigger:** when the user's `rank[]` order changes during pressure-test (via the conflict prompt's `Re-order — gut wins →` button), pairs are re-generated for any pairs not yet walked. Already-walked pairs stay in state with their picks.

**Modal · Pair screens (one per pair)**

After intro, the user walks each pair. Each pair screen:

- **Counter eyebrow** (uppercase, gold): `PAIR {X} OF {Y}` — e.g. `PAIR 3 OF 6`
- **Prompt** (italic Georgia, ~22px, centered, max-width 540px): `When **{Value A}** and **{Value B}** *collide* — which wins?` (A and B in gold)
- **Helper line below prompt** (small, faint): `Gut-pick. No overthinking.`

**Two pair-cards side-by-side:**

Each card:
- Padding 24px, gold-line border by default, hover state with `--gold` border + slight lift
- Click state: gold border + `--gold-warm` background tint + ★ in top-right corner
- Content:
  - **Value name** (serif 26px gold)
  - **Definition** (italic Georgia, ~15px, in curly quotes)
  - **Keystone footer block** (separated by a top border in `--gold-line`):
    - Label (uppercase, gold, small): `KEYSTONE`
    - Behavior name (single line)
    - **If `keystoneId` is null:** label still shows `KEYSTONE`, body shows `No keystone set` in faint italic gray. Doesn't block the pair from working.

**Skip link** below the pair-cards: `Skip — they don't actually compete for me` (underlined gold text, small)

**Behavior on card click (non-conflict):**
1. Animate the picked card to `.selected` state (gold border, gold-warm tint, ★ appears)
2. 600ms beat
3. Write to state: `pressureTest.pairs[currentIdx] = { aId, bId, pickedId: clickedClusterId, matchedRank: true }`
4. Advance to next pair

**Behavior on card click (conflict — user picked the lower-ranked value):**
1. Animate the picked card to `.selected` state (no auto-advance)
2. Render **conflict prompt** as a burgundy-bordered card BELOW the pair-cards (inline, not a separate modal):
   - Label (burgundy uppercase, small): `YOUR GUT SAID SOMETHING DIFFERENT`
   - Body (italic Georgia): `You picked **{picked value name}** — but you ranked **{other value name}** higher. Want to re-order, or stand by your stated rank?`
   - Two buttons:
     - `Re-order — gut wins →` (filled gold)
     - `Stand by my rank` (outlined gold)
3. **On Re-order click:** swap the two values in `state.mirror4.rank[]`, increment `pressureTest.rankChanges`, write to pair state with `matchedRank: true` (after re-order, gut now matches rank), advance to next pair after 300ms
4. **On Stand-by click:** leave rank unchanged, write pair state with `pickedId` set to the actual gut-picked value and `matchedRank: false`, increment `pressureTest.conflicts`, advance to next pair after 300ms

**Behavior on skip:**
- Write pair state: `{ aId, bId, pickedId: null, matchedRank: false }`
- Advance after 300ms

**Determining "conflict":** `matchedRank` is `true` if and only if the user's pick is the value currently positioned HIGHER (lower index) in `state.mirror4.rank[]` at the moment of the pick. So pick of the lower-ranked value triggers the conflict prompt. The `pressureTest.conflicts` counter only increments on Stand-by (the user kept the conflict). Re-orders resolve the conflict.

**State schema additions**

From the Section 1 `Mirror4State` type, this ship populates:

```typescript
rank: string[];                          // array of cluster IDs, top = highest

pressureTest: {
  complete: boolean;
  pairs: Array<{
    aId: string;                         // cluster id
    bId: string;                         // cluster id
    pickedId: string | null;             // null if user skipped
    matchedRank: boolean;
  }>;
  conflicts: number;
  rankChanges: number;
};
```

All writes through `saveMirror4State()`. 5.6c routing handles the room-level resume.

**Active pair index:** track which pair the user is currently walking. Store as `state.mirror4.pressureTestActivePairIdx` (or as a `currentPairIdx` field on the `pressureTest` object — Agent's call). Refresh inside the pressure-test modal resumes Rank room (without the modal — modals reopen closed), but on next Begin pressure-test click, the user picks up at the active pair.

**Definition of done**

- User completes Discover + Behaviors (all named values have ≥1 behavior), Continue to Rank enabled, click → Rank room opens.
- Rank screen renders with title, subtitle, helper ribbon.
- Phase 1 rank stack shows N numbered rows (one per named value) in initial cluster-creation order.
- Each row shows value name, definition, keystone line (or "not set"), drag handle, ▲ ▼ arrows.
- Top row's ▲ is disabled. Bottom row's ▼ is disabled.
- ▲ ▼ click reorders rows AND updates `state.mirror4.rank[]`.
- Drag a row → drop in new position → reorders correctly, state updates.
- Phase 2 Begin Pressure-Test card shows correct pair count for N values (cap 10 at N≥5).
- Continue button is disabled with helper `Complete the pressure-test first.`
- Click Begin pressure-test → modal opens to Intro screen with example.
- Click `Got it — start →` → first pair screen renders.
- Pair card click matching rank: animates selected, 600ms beat, advances to next pair without conflict prompt.
- Pair card click against rank: shows conflict prompt with both Re-order and Stand-by buttons.
- Re-order swaps the two values in `state.mirror4.rank[]` AND increments `rankChanges`. Advances after 300ms.
- Stand-by leaves rank unchanged AND increments `conflicts`. Advances after 300ms.
- Skip link writes `pickedId: null` and advances.
- After all pairs walked: Done screen shows correct subtitle variant based on conflicts/rankChanges counters.
- `Continue to Claim →` sets `pressureTest.complete = true`, closes both modal and Rank, opens Claim placeholder.
- After completion, Continue button in Rank footer is enabled (no helper).
- Walked pairs render with subtle gold-warm tint on the rank stack rows.
- Closing pressure-test modal mid-walk preserves state. Reopening: skip intro, resume at active pair.
- Page refresh on Rank room (modal closed) lands back on Rank room with rank state intact. Reopening modal resumes correctly.
- Page refresh on Rank room with pressureTest.complete = true: Rank shows tested-state visuals, Continue is enabled.
- All previous sections (1, 2, 3a/3b, 4, all polish) work unchanged.
- No new design tokens added (or flagged and approved).
