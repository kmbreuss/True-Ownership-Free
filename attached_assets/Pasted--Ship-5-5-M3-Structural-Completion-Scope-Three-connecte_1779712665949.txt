### 2. ADD: Gift Inventory bar (sticky at top)

New component between the help card and the first cluster card.

**Structure:**
- Sticky position at top of the room body (under the room header but above cluster cards)
- Background: `var(--bg-card)` with `var(--gold-border)` border

- Body: 5 theme rows (Mind, Heart, Spine, Spark, Hands) with theme color label on left and chips on right

### 3. ADD: "Which creature?" picker (popover)

Triggered by:
- User adds a new gift via "+ add" (gift just got added to inventory, needs a home)
- User taps any gift chip from the inventory bar (move action)
- User taps any gift chip inside a cluster card's gift bin (move action)

**Visual:**
- Small floating panel, anchored near the tapped chip
- Background: `rgba(15, 26, 48, 0.95)`, gold 1px border, 8-radius
- Width: ~380px
- Header: gold uppercase tracked label, then italic serif sentence
  - For add: *"Which creature carries {giftName}?"*
  - For move: *"Move {giftName} to which creature?"*
- Body: vertical stack of creature buttons (one per existing cluster)
  - Each button: emoji + full descriptor name (e.g. "🦅 Gracefully Wise Eagle")
  - Current creature (if move action) appears grayed/disabled
- Footer: italic helper text *"Tap the creature that carries this gift in its power"*

**Behavior:**
- User taps a creature → picker closes, gift moves to that cluster, inventory + cluster cards update instantly
- Tap outside or Escape → picker closes, no action taken (move action only — add action requires placement)

### 4. ADD: Superpower sentence at bottom of every cluster card

**Position:** Below the gift chip bin, separated by a 1px dashed gold rule

**Structure:**
- Label (uppercase tracked gold, 10px): "★ THE {CREATURE NAME}'S SUPERPOWER" or "★ YOUR {CREATURE}'S SUPERPOWER"
- Sentence stem (italic serif, 15px, gold): `"In my power, the {animal} [BLANK 1], [BLANK 2], and [BLANK 3]."`
- Three inline blanks:
  - Blank 1 placeholder: *"what I do well"*
  - Blank 2 placeholder: *"what it gives me"*
  - Blank 3 placeholder: *"what it gives others"*
- Empty blanks: gold-tinted background, dashed gold border, muted italic placeholder

**Validation:** All three blanks must be filled across ALL clusters for `Continue to Under Pressure →` to enable (disabled at 50% opacity until valid). Same hard validation pattern as Under Pressure's shadow sentence.

### 7. STATE LOGIC

**Auto-assignment vs manual placement:**
- Gifts that came from Step 1a (Your Gifts) → auto-assigned to clusters by the existing archetype-matching system (unchanged behavior)
- Gifts added on Superpowers via "+ add" → manually placed via the "Which creature?" picker
- Both kinds of gifts can be moved any time

**State sync:**
- New gifts added on Superpowers flow back into `state.mirror3.pickedGifts` so Step 1a stays in sync
- Per-theme 5-cap from Step 1a still applies — "+ add" button on a theme that's already at 5 is disabled with tooltip *"5 max per theme — clear one in Your Gifts first"*
- Moving a gift between clusters preserves the gift's state (Owned vs Emerging)

**Re-entry preservation:** All edits (cluster names, animals, descriptors, Superpower sentences, gift placements) preserve across visits. Existing `m3SyncStateToPicks` helper handles this — verify it still works after the inventory bar is added.

## Gate 5.5d — Personalization audit + standards doc

### Personalization audit

**Phase 1 — Grep:** Find every literal `"User"` string in the codebase (case-sensitive, whole word). Surface a list to the owner with file path + line number + surrounding context for each occurrence.

**Phase 2 — Classify each occurrence:** Owner reviews the list with Claude and marks each as:
- **Replace with user's name** (most common — e.g. greetings, claims, "User's Map of Me")
- **Replace with "you/your"** (where second-person makes more sense than name)
- **Leave as-is** (genuine UI labels like form placeholders, dev artifacts, schema field names)

**Phase 3 — Implement:** Update the marked occurrences. Wire `state.user.displayName` lookup. For pages where personalization is currently absent but should be present (owner will identify these on review), add the name wiring.

**Where to source the name:** Existing `/api/me/profile` endpoint returns user profile. The `users.display_name` column is the source of truth (per S23 work).

**No-name fallback:** If a user hasn't set a display name yet, fall back to "you" / "your" (second-person voice). Never display literal "User" or empty placeholder.

### Standards doc update

Update `AG45_App_Standards.md` (in `/docs/` or wherever it lives in the repo) with:

**Section 1 update:** Add veil text for Superpowers room rename — *"Giving them a shape…"* line stays unchanged but Section 1's room mapping changes Animals as Anchors → Superpowers.

**Section 2 update:** Add the new Continue button: `Continue to Superpowers →` (rename from `Continue to Animals →`).

**Section 5 update — Room architecture:** Add the new Gift Inventory bar pattern. Sticky at top of Superpowers room. Theme color-coded. Add/move via "Which creature?" picker. New section.

**Section 6 update — Sentence completion grammar:** Add the M3 Superpower sentence stem: `"In my power, the {animal} [what I do well], [what it gives me], and [what it gives others]."` Note that it mirrors the Shadow sentence's three-blank architecture, opposite tone.

**New Section 11 — Personalization:**
- Source of truth: `users.display_name` via `/api/me/profile`
- Fallback when no name set: "you" / "your" (second person)
- Never display literal "User" string anywhere user-facing
- Standard greeting pattern: *"Welcome back, {name}"* or *"Welcome back"* if no name

**New Section 12 — Variable count templates:** Document the Power roll-up / Shadow roll-up / Subhead templates for 1-5 creature counts on Own It. Same pattern applies to any future variable-count surfaces.
