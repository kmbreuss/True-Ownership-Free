# AG45 True Ownership · App Standards (v1.0)

**What this is:** The single source of truth for app-wide patterns, constants, and conventions across the True Ownership app (Boardroom + Owner's Circle). Read this before every ship. Update it when patterns change.

**Why:** Without a standards doc, every ship is a guess at what the inherited pattern is. This eliminates drift.

**Rule for Replit Agent:** Standards in this doc are *defaults* — only override with explicit owner approval, and update this doc when approved overrides become the new standard.

---

## 1 · Veil Transition (room entry)

**Single source of truth:** `NA1_VEIL_TIMING` constant in `App.tsx`. Used by M1 (Purpose), M2 (Vision · 5 rooms), M3 (Identity · 4 rooms). Future mirrors inherit.

### Current locked values

```typescript
NA1_VEIL_TIMING = {
  holdAt: 1100,      // ms — peak hold, gold text held at center
  fallingAt: 1800,   // ms — veil begins peel from top
  idleAt: 2800       // ms — total cycle complete, room interactive
}
// Total: ~2.2 seconds
```

### Visual stages

| Stage | Duration | What happens |
|---|---|---|
| Rise | 0–600ms | Radial gold-tinted veil sweeps up from bottom |
| Text fade-in | 400–900ms (overlaps) | Italic Georgia gold serif line rises + fades in |
| **HOLD** | 900–1800ms | User reads threshold line · screen swap happens invisibly underneath |
| Text fade-out | 1500–1800ms | Threshold text fades |
| Fall | 1800–2500ms | Veil peels back from top |
| Settle | 2500–2800ms | Room fully interactive |

### Veil text per room (italic Georgia gold serif)

**Mirror 1 — Purpose**
- Room entry → *"Stepping into the room with Katherine…"*

**Mirror 2 — Vision**
- Two Futures → *"Looking out ten years…"*
- Time · 10-Year → *"Stepping into the life you'll own…"*
- Wealth · 10-Year → *"Stepping into what you'll build…"*
- Self · 10-Year → *"Stepping into who you'll be…"*
- Vision Declaration → *"The moment of claiming…"*

**Mirror 3 — Identity**
- Your Gifts → *"Looking at what you carry…"*
- Animals as Anchors → *"Giving them a shape…"*
- Under Pressure → *"Where the gifts go shadow…"*
- Own It → *"The moment of claiming…"*

### Rules

- **Veil fires only on room ENTRY, never on internal screen swaps.** Two Futures has 8 internal screens but only 1 veil (on entry).
- **Veil fires only for rooms in "Up next" or "In progress" state.** Locked rooms are tap-inert — no veil, no overlay, no transition.
- **CSS class `.na1-veil` is the single shared component.** Do not fork per-mirror. Future timing changes propagate from one constant.

## 2 · Continue Button Pattern

**Standardized across the entire app.** Sentence case, with arrow, naming the next destination.

### Format

`Continue to [Next Room Name] →`

### Examples (locked)

**Mirror 2 — Vision (internal room-to-room):**
- End of Two Futures → `Continue to Time →`
- End of Time → `Continue to Wealth →`
- End of Wealth → `Continue to Self →`
- End of Self → `Continue to Vision Declaration →`
- End of Vision Declaration (first claim) → `Continue to Identity →`

**Mirror 3 — Identity (internal room-to-room):**
- End of Your Gifts → `Continue to Animals →`
- End of Animals as Anchors → `Continue to Under Pressure →`
- End of Under Pressure → `Continue to Own It →`
- End of Own It → `Continue to Values →` (lands when M4 ships)

### Exceptions

- **Inter-screen continues within a single exercise** stay generic `Continue →`. Two Futures internal screens (e.g. screens 3 and 7 of the chip-ladder flow) use plain `Continue →` because they advance to the next *screen of the same exercise*, not a new room.
- **Test for which to use:** if the destination is a new named room on the hub, use `Continue to [Name] →`. If the destination is the next internal screen of the current exercise, use `Continue →`.

### Styling

- Sentence case throughout — capital C on "Continue," capital first letter of each word in the room name
- Trailing arrow → (single character, not the unicode block arrow)
- Disabled at 50% opacity until validation passes
- Right-aligned in the room footer

## 4 · Typography

### Fonts

- **Body:** Inter (or system fallback)
- **Serif headings · editorial italic:** Cormorant Garamond (or Georgia fallback for body italic prose)
- **Veil text:** italic Georgia (NOT Cormorant — Georgia is the system fallback that renders consistently across devices)

### Type scale

| Element | Size | Weight | Tracking | Color |
|---|---|---|---|---|
| **Eyebrow** (room label) | 10–11px | 700 | 0.18–0.22em | Gold uppercase |
| **H1** (room title) | Serif, ~32px | Regular | — | Default text |
| **Subhead** (italic gold serif) | ~18px | Italic | — | Gold |
| **Help card text** | ~15px | Italic | — | Gold inside burgundy border (Under Pressure) or gold border (other rooms) |
| **Body prose** | 16px | Regular | — | Default |
| **Filled blanks** (sentence completion) | Inherits prose size | Italic | — | Lens color |

### Eyebrow format

```
MIRROR [N] OF 4 · STEP [N] · [ROOM TITLE]
```

Examples:
- `MIRROR 3 OF 4 · STEP 1 · SHAPE YOUR VERSIONS`
- `MIRROR 3 OF 4 · STEP 3 · UNDER PRESSURE`

## 6 · Sentence Completion Grammar

### Pattern

`"[Stem opening], [blank 1], and [blank 2]."` (M2 — two blanks · "behavior + proof")
`"[Stem opening], [blank 1], [blank 2], and [blank 3]."` (M3 Under Pressure — three blanks · "what I do + what it costs me + what it costs others")

### Rules

- Each blank is a **full-width line-break input below the corresponding sentence half** — NOT inline (except Under Pressure where the three blanks are inline)
- Placeholder: italic muted serif, lowercase
- Gold-tinted background until filled
- Once filled, user's words render in **lens color italic serif** (lens color depends on the room)
- Auto-saves on blur or Cmd+Enter
- **Validation:** all blanks must be filled to mark the exercise complete

### M2 Templates (locked)

| Domain | Lens | Sentence template |
|---|---|---|
| Time · Work | Yellow | "In 10 years, {chip}. I do this by ___, and the work itself feels like ___." |
| Time · Family | Yellow | "In 10 years, {chip}. I make this real by ___, and what I notice in our time together is ___." |
| Wealth · Cashflow | Green | "In 10 years, {chip}. I keep it healthy by ___, and what it lets me say yes to is ___." |
| Wealth · Building | Green | "In 10 years, {chip}. The way I build wealth is ___, and what I'll have at the end of the decade is ___." |
| Self · Self-treatment | Purple | "In 10 years, {chip}. I do this by ___, and in my body it feels like ___." |
| Self · Self-perception | Purple | "In 10 years, {chip}. The story I tell about myself is ___, and the inner voice I hear is ___." |

(Full M2 template table in `Replit_Handoff_Mirror2_Full.md`)

### M3 Template (Under Pressure)

```
"When the {animal} goes shadow, [what I do], [what it costs me], and [what it costs others]."
```

- Three blanks inline (not full-width line breaks like M2)
- Placeholder words: *what I do · what it costs me · what it costs others*
- Filled text renders in burgundy italic Georgia (matching the Under Pressure lens)

## 7 · State Logic

### Mirror progression

- Mirror N unlocks when Mirror N-1 is complete (production behavior)
- `?newM[N]=1` URL flag overrides the unlock for testing (dev convenience only — removed before launch)
- Sticky localStorage opt-in: once flag is set, subsequent loads keep mirror unlocked unless `?newM[N]=0` explicitly turns it off

### Room progression within a Mirror

- Room N+1 unlocks when Room N is complete
- Locked rooms are tap-inert: no click handler, no veil, no overlay
- Locked-state copy: *"Unlocks after [previous room name]"*

### "Complete" derivation rules

| Room type | Derivation |
|---|---|
| Pick-style (Your Gifts) | `pickedCount >= 1` (soft) |
| Shape-style (Animals as Anchors) | All clusters: name + animal + 2 descriptors + ≥1 gift |
| Under Pressure | Every picked gift has ≥1 shadow + 1 primary flagged · 3-blank sentence filled per cluster |
| Declaration / Seal | User has claimed (clicked the claim button at least once) |

### State sync on re-entry

- Rooms rebuild from current state on every entry — never trust cached state from prior visits
- Manual edits (cluster names, animals, descriptors, picked shadow chips) preserved when underlying gift selection changes
- Stale entries (shadows for gifts no longer picked) pruned automatically

## 8 · Constants Architecture (mirror3Constants.ts pattern)

When shipping content + a feature gate, **both must land in the same ship**:

```typescript
// Content
SHADOW_LIBRARY[gift.label] = ["word1", "word2", "word3", "word4"]

// Gate
SHADOWS_AVAILABLE[theme] = true
```

**Lesson from M3 Ship 5:** content was added but gate stayed `false`, hiding all the new content. Always pair content updates with their gates.

### Pattern for future feature-gated content

1. Write content into the constant array/object
2. Flip any associated `*_AVAILABLE` boolean to `true`
3. Update the comment above the constant to reflect new coverage
4. Verify with grep that no other gate references the old `false` state

## 9 · Mobile / Responsive

- Mobile renders at 375px minimum
- Card grids collapse to single column
- Room expands to nearly full-screen (95vh max)
- Sentence-completion blanks stack vertically below their sentence stems
- Sub-progress pips remain visible at top of multi-step exercises
- Map of Me button collapses to gold dot, label hides
- Save buttons stay sticky-bottom on mobile

## 10 · Development Workflow Rules

### Each ship requires

- Owner sign-off at each ship gate (no auto-advance)
- Clean localStorage demo before sign-off
- Typecheck baseline maintained (zero new errors)
- HMR clean (no console warnings introduced)
- Architect review before final commit

### Naming

- **Disciplines:** the 5 As at top (A1 All In It, A2 Align With It, A3 Advocate For It, A4 Act On It, A5 Accountable To It). Journey verbs always capitalized: Align, Advocate, Act, Account.
- **Mirrors:** the cards inside each A (every exercise = looking inward). A1 has 4 Mirrors: Purpose, Vision, Identity, Values.
- **Rooms:** the sub-exercises inside each Mirror.

### File pasting

- Replit silently truncates pastes over ~7–8KB. Keep edit chunks under ~3KB.
- Use single paste blocks for multi-line edits.
- Re-fetch + verify file via console fetch after save.
